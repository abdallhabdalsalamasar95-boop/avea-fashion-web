# برومبت تنفيذي: إعادة القطعة للمخزون فور الإلغاء أو الإرجاع مع إرسال الطلبات إلى درب السبيل

## الدور
أنت مهندس Backend وAndroid Kotlin/Jetpack Compose ولوحة تحكم خبير في نظام Carmen Karla. طبّق هذا المنطق كما هو، بدون إضافة مسار تلف أو منع بيع أو انتظار فحص:

> عند تحوّل طلب إلى `canceled` أو `returning`، تعود القطعة فورًا إلى مخزون البيع ليستطيع أي زبون حجزها أو طلبها. ومع ذلك تبقى في لوحة التحكم رسالة تشغيلية واضحة بأنها **راجعة وليست موجودة فعليًا في المخزن حتى الآن**.

---

## القاعدة التجارية المطلوبة

### عند إلغاء الطلب `canceled`
- أعد كمية كل منتج ومقاس ولون فورًا إلى المخزون المتاح:
  - `availableStock`
  - `stockQuantity`
  - `sizeQuantities`
- نفّذ إعادة المخزون مرة واحدة فقط باستعمال `inventoryRestoredAtMs` أو `movementId`.
- تصبح القطعة قابلة للحجز والطلب مباشرة من الزبائن الجدد.
- لا تحتاج إلى فحص تلف أو حالة مخزون تالف؛ الفساتين لا تُعامل كتالف في هذا المسار.

### عند حالة قيد الإرجاع `returning`
- أعد كمية كل منتج ومقاس ولون فورًا إلى المخزون المتاح، بنفس منطق الإلغاء.
- لا تنتظر وصول القطعة الفعلي إلى المخزن قبل إعادتها إلى مخزون البيع.
- لا تعرضها كـ `نفدت الكمية` للزبونة.
- اسمح للزبونة بإضافتها إلى السلة وحجزها أو إنشاء طلب جديد عليها.
- تبقى حالة الطلب الأصلي `returning` لأغراض التتبع والتدقيق فقط.

### التمييز بين المخزون والحالة الفعلية
يوجد جانبان منفصلان ويجب عدم خلطهما:

1. **مخزون البيع (`availableStock`)**
   - يعود فور الإلغاء أو الإرجاع.
   - الزبونة تستطيع الطلب منه مباشرة.

2. **حالة القطعة الفعلية في لوحة التحكم**
   - تبقى: `راجعة وليست في المخزن فعليًا`.
   - تستخدم فقط للتنبيه الإداري ومتابعة الشحنة.
   - لا تمنع الطلب الجديد ولا تخفض المخزون المتاح.

---

## إرسال الطلب الجديد إلى درب السبيل

عندما يطلب زبون قطعة أُعيدت إلى المخزون بسبب `canceled` أو `returning`:

1. تحقق من توفر الكمية الحالية في `availableStock` أو `sizeQuantities`.
2. احجز الكمية للطلب الجديد بصورة عادية.
3. أنشئ طلبًا جديدًا برقم `orderId` جديد.
4. أرسل الطلب الجديد إلى درب السبيل مباشرة وفق دورة الطلب الطبيعية.
5. يجب أن يرجع درب السبيل رقم شحنة أو رقم تتبع.
6. إذا لم يرجع رقم تتبع من درب السبيل:
   - لا تعتبر الطلب الجديد ناجحًا.
   - أرجع كمية الطلب الجديد للمخزون مرة واحدة.
   - اعرض رسالة عربية واضحة للزبونة:
     > `تعذر إتمام الطلب لأن شركة التوصيل لم تصدر رقم تتبع. حاولي مجددًا بعد مراجعة بيانات التوصيل.`
7. لا تعدّل أو تلغي حالة الطلب الأصلي العائد عند إنشاء الطلب الجديد؛ لكل طلب رقم وحركة مخزون مستقلة.

---

## قواعد منع التكرار

### إعادة مخزون الطلب الأصلي
- استخدم `inventoryRestoredAtMs` أو سجل حركة مخزون فريد.
- إذا أصبحت الحالة `canceled` أو `returning` أكثر من مرة، لا تزد الكمية مرتين.
- لكل حركة سجل مثل:

```text
movementId: return_to_sale_<orderId>_<timestamp>
orderId: رقم الطلب الأصلي
productId: المنتج
size: المقاس
color: اللون
quantity: الكمية
reason: canceled_or_returning_immediate_stock
performedAtMs: وقت الحركة
```

### حجز الطلب الجديد
- عند الطلب الجديد، انقص فقط من المخزون الحالي المتاح.
- لا تربط الطلب الجديد بحركة مخزون الطلب العائد إلا للعرض والتدقيق.
- لا تسمح بإنشاء طلبين جديدين من نفس آخر قطعة إلا باستخدام قفل مخزون (`_INVENTORY_LOCK`) أو عملية atomically آمنة.

## لوحة التحكم

### رسالة إلزامية للطلبات العائدة
عندما تكون الحالة `returning`، اعرض شارة ورسالة واضحة في تفاصيل الطلب وفي مركز التنبيهات:

> `الشحنة راجعة وليست في المخزن فعليًا حتى الآن. تمت إعادة كميتها إلى مخزون البيع حسب سياسة المتجر، ويمكن للزبائن حجزها في طلبات جديدة.`

### بطاقة الطلب العائد
اعرض:

- رقم الطلب الأصلي.
- اسم العميلة.
- المنتجات والمقاسات والألوان والكميات.
- رقم شحنة درب السبيل.
- سبب الإرجاع إن وجد.
- خط زمني للشحنة.
- شارة واضحة: `راجعة — ليست في المخزن فعليًا`.
- شارة ثانية: `تمت إعادة الكمية لمخزون البيع` عند وجود `inventoryRestoredAtMs`.

### مركز التنبيهات
أضف تنبيهًا لكل طلب عائد:

```text
المستوى: متابعة
العنوان: شحنة راجعة
النص: الطلب #[رقم الطلب] راجع من درب السبيل وليس موجودًا فعليًا في المخزن.
معلومة المخزون: تم إرجاع [الكمية] قطعة إلى مخزون البيع حسب سياسة المتجر.
```

### عرض المخزون
في صفحة المنتج، اعرض للمدير رقمين منفصلين:

- `متاح للبيع`: الكمية التي يمكن للزبائن طلبها الآن، وتشمل القطع المعادة فور الإلغاء أو الإرجاع.
- `شحنات راجعة خارج المخزن`: عدد القطع التي ما زالت في الطريق إلى المخزن، للمتابعة فقط.

لا تجعل رقم `شحنات راجعة خارج المخزن` يمنع الطلب أو يخصم من `متاح للبيع`.

---

## تطبيق الزبونة

### صفحة المنتج
- إذا أعيدت كمية المنتج بسبب إلغاء أو إرجاع، تظهر ككمية متاحة عادية.
- الزبونة تستطيع اختيار المقاس واللون وإضافتهما للسلة.
- لا تعرض للزبونة تفاصيل أن القطعة كانت في طلب راجع أو ملغي.

### تأكيد الطلب
- يتم إنشاء طلب جديد مستقل.
- يرسل إلى درب السبيل.
- عند نجاح درب السبيل ورجوع رقم التتبع، تظهر شاشة نجاح الطلب كالمعتاد.
- عند فشل درب السبيل في إصدار رقم التتبع، اعرض رسالة الخطأ العربية فقط ولا تحفظ طلبًا ناقصًا.

---

## تطبيق المندوبة

- إذا طلبت المندوبة قطعة أعيدت إلى مخزون البيع، تُعامل كطلب مندوبة عادي.
- يسجل الطلب الجديد في `طلبات عميلاتي` ويُرسل إلى درب السبيل.
- العمولة لا تعتمد إلا بعد `delivered` للطلب الجديد.
- لا تحتسب عمولة للطلب الأصلي `canceled` أو `returning`.
- لا تكشف للمندوبة أي معلومات داخلية عن أن القطعة ما زالت راجعة إلا إذا كانت هي مسؤولة عن الطلب الأصلي وفي صفحة تفاصيله.

## API المطلوبة

### بيانات حالة الطلب
أعد الحقول التالية للوحة التحكم:

```json
{
  "status": "returning",
  "inventoryRestoredAtMs": 0,
  "inventoryRestored": true,
  "physicalWarehouseStatus": "returning_not_in_warehouse",
  "physicalWarehouseMessage": "الشحنة راجعة وليست في المخزن فعليًا حتى الآن.",
  "externalDelivery": {
    "provider": "darb_sabeel",
    "trackingNumber": "...",
    "referenceCode": "..."
  }
}
```

### منطق نجاح الطلب الجديد
- لا يرجع endpoint إنشاء الطلب `ok: true` إلا إذا وصل رقم تتبع أو رقم مرجع من درب السبيل.
- عند فشل الشحن، أرجع:

```json
{
  "ok": false,
  "code": "missing_darb_sabeel_tracking",
  "error": "تعذر إتمام الطلب لأن شركة التوصيل لم تصدر رقم تتبع. حاولي مجددًا بعد مراجعة بيانات التوصيل."
}
```

## الاختبارات المطلوبة

- [ ] طلب `canceled` يعيد الكمية إلى المخزون المتاح فورًا مرة واحدة فقط.
- [ ] طلب `returning` يعيد الكمية إلى المخزون المتاح فورًا مرة واحدة فقط.
- [ ] القطعة العائدة تظهر متاحة للزبونة ويمكن إضافتها للسلة.
- [ ] لوحة التحكم تعرض: `راجعة — ليست في المخزن فعليًا`.
- [ ] الطلب الجديد على القطعة ينشأ برقم جديد ويُرسل إلى درب السبيل.
- [ ] لا يعتبر الطلب الجديد ناجحًا إذا لم يرجع درب السبيل رقم تتبع.
- [ ] فشل رقم التتبع يعيد كمية الطلب الجديد للمخزون.
- [ ] لا تتكرر زيادة المخزون عند إعادة محاولة تحديث نفس الطلب العائد.
- [ ] لا تُحتسب عمولة للطلب الأصلي الملغي أو العائد.
- [ ] العمولة للطلب الجديد تعتمد فقط عند `delivered`.
- [ ] اختبر حالة وجود طلب عائد وطلب جديد على نفس المقاس مع قفل المخزون لمنع البيع الزائد.
